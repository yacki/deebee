## 验收发现并修正的问题

1. SSH 协商可能选择与登记指纹不同的主机密钥：显式配置算法，并在认证前校验。
2. MySQL 默认游标会全量缓存：读查询换成流式游标，PG 使用服务端游标；截断时正确结束连接，避免继续排空超大结果。
3. MySQL 流式游标 rowcount 的未知值不能当 affected_rows：查询统一返回 0。
4. 恢复执行记录必须在获取实例锁之后，第二个 worker 不能把正常任务误标重启。
5. 带 `/deebee` 部署前缀的 MCP 地址与 metadata 必须带正确 root_path，已增加挂载路径测试。
6. 账号重新核验失败要阻断后续授权，不能保留旧的“已启用”绕过状态。
7. 测试 SSH 镜像 sudo 白名单指向 `/usr/bin/touch`，但 Alpine 工具在 `/bin`：修正测试镜像，重新跑通普通拒绝/特权允许。

## 最终签收边界

- 尚未接入用户指定的真实企业 IdP 或具体外部 AI Agent 产品；独立 MCP SDK 客户端验证的是协议和服务执行，不冒充那个产品的最终验收。
- 尚未做生产网络/证书链部署验收、异机备份恢复、物理断电故障注入、容量压力和独立渗透测试。存储重开解密、重启恢复逻辑、写入失败拒绝分派及 TLS/指纹负例已测试。
- 不自动部署、合并或推送此分支；原 RDP 不在新能力范围，也没有在本轮重新搭建 Windows 远程桌面环境。
- 未运行硬编码旧环境且会建删表的整套浏览器 E2E；已用隔离环境进行上述真实原 UI 回归，保留该区别。
- V1 是单实例静态授权服务，不提供逐次审批、临时特权账号签发、分布式执行、任意 SQL 沙箱或 SSH 子进程强制回收保证。
