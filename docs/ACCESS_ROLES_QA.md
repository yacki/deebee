默认检查：

```sh
backend/.venv/bin/pytest -q backend/tests
npm test
npm run lint
git diff --check
```

实际协议测试需先启动 `backend/tests/access_lab/compose.yml`，并启动指向全新临时数据目录的测试后端；后端需显式开启本地隔离测试的非 TLS 开关。进入 `backend` 目录后，设置 `COMPOSE_PROJECT_NAME` 为隔离项目名、`DEEBEE_ACCESS_LIVE_URL` 为回环测试 URL，再运行两个 live 测试文件。

浏览器测试使用 `DEEBEE_WEB_URL`、`DEEBEE_API_URL` 和 `DEEBEE_ROLE_UI_URL` 指向隔离实例。RDP 额外设置 `DEEBEE_ROLE_RDP_HOST` 为测试 guacd 能解析的 xrdp 主机名，使用 `tests/fixtures/rdp/Dockerfile`。本次将匹配该主机名的测试证书安装到独立 guacd 的 CA 信任库，未关闭证书校验。Playwright 输出报告和截图位于忽略提交的 `playwright-report/`、`test-results/`。

验收中同时修复了原工作台测试对固定远端地址、SQL 历史文本的脆弱定位，以及 xrdp 测试容器重启时残留 PID 的问题。

## 边界

RDP 的实测目标是 Linux xrdp，验证的是 RDP 协议、账号选择、画面、录像及撤权；未连接真实 Windows/AD 域。Kubernetes 的用户组边界采用受控驱动替身测试，未启动真实 Kubernetes 集群。独立 OIDC 活体环境未启动；已有身份验证单元测试通过，本次人员本地登录、API Key 与 MCP 均做了真实请求验收。

本次不包含个人同名账号供应、在远端自动建号、动态标签继承、用户组嵌套或管理后台 RBAC。运行任务撤权不能撤回已经发生的远端修改，`unknown` 仍需核验远端状态。
