# RDP 故障与全功能回归记录

验收日期：2026-10-20，Australia/Perth。

## 线上 RDP 的实际结果

已在用户正在使用的 `https://deebee.idmesh.site/deebee/` 复现 `100.80.0.35` 连接失败。故障时，本机能连接 Windows 的 3389 端口，DeeBee 服务器 `100.80.0.202` 连接同一端口超时；服务器至 SSH 目标的连接最初也超时。检查了 Tailscale 路由、中继、TCP 和 RDP X.224/TLS 握手，并刷新服务器的连接探测和 UDP 绑定。随后 SSH 恢复直连，Windows 的 TCP、RDP 握手及网页桌面恢复。

恢复后使用**主网关、原连接和真实 Windows** 验收：画面显示、键盘 Ctrl+Esc 打开开始菜单、鼠标打开开始菜单、全屏/退出全屏及尺寸恢复。页面持续显示已连接、录制中；原来的数据库查询和表标签仍保留。没有用 xrdp 代替本次线上 Windows 验收。

Windows 当前证书的 SHA256 与原有 `known_hosts2` 一致：`5e:7a:78:1f:24:e0:ca:8c:52:71:70:c7:67:99:43:0b:8a:f2:c9:d7:32:53:fd:5f:af:3c:f9:41:8a:eb:8a:3f`。没有修改指纹、关闭证书校验或更改资源凭据。排查过程中出现过 TLS 错误提示，但不能据此断定证书已经更换。排查恢复阶段没有重启主后端和主 guacd；后续授权发布重启了后端，详见发布状态。

这是本次连接恢复的实测结果，不保证外部 Tailscale 中继链路永不抖动。

## 本次额外发现并修复的四处代码问题

| 问题 | 修复与回归证据 |
|---|---|
| RDP 认证/证书失败后切回标签会再次认证；重试耗尽后切标签也会继续尝试 | 保留会话的重试资格及次数，切标签遵守原限制；用户明确点击重新连接时才重置次数。三个新增用例先复现失败，修复后通过。另补 Windows 音频、光标和流式 PNG 初始化用例。 |
| 数据库连接响应较慢时切到 RDP/K8s，旧请求使用当前远程连接 ID 请求 SQL 元数据，甚至抢回标签 | 为连接初始化增加代次校验，忽略过期初始化；元数据请求固定原连接，过期响应不覆盖新连接。延迟数据库响应的新增用例先失败、后通过。 |
| K8s 用户名留空，导致整个资源池同步和后台资源列表失败 | Kubeconfig 连接保留资源配置提示，不创建无效的独立账号；Bearer Token 连接使用账号展示占位，身份仍由 Token/RBAC 核验。两个新增用例先失败，14 项资源池测试通过；真实集群及容器终端通过。 |
| 查询执行中回收 MySQL 会话，回滚与查询并发读写同一协议流，产生包序号错误或连接丢失 | 关闭和回滚使用查询相同的会话锁，等待当前语句结束后关闭。真实 `SLEEP(0.3)` 并发回收用例先失败，修复后 MySQL 专项 5 项通过。长查询的关闭可能需要等待当前语句结束。 |

运行时代码涉及 `src/App.vue`、`src/components/RdpDesktop.vue`、`backend/deebee/access/connection_pool.py`、`backend/deebee/mysql.py`。保留了工作区已有的其他改动；没有提交或推送 Git。
