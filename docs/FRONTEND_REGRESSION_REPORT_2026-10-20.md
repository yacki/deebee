## 结论与判定方式

**本次目录与布局修复后，135 个独立浏览器用例通过，其中目录/布局专项 12 项；线上实际 `idmesh` 的 66 张表和隔离临时数据库补充复测通过。前次 79 项验证没有覆盖截图中的对象目录长元数据布局，不能证明该页面没有重叠；本次补齐这个范围。** 前端与 PG 权限接口后端修复均已上线。此前经用户确认已发布 PG 后端修复，线上实际接口和菜单验证通过；本次补充仅更新前端。不能把本轮结果等同于全部协议、全部历史需求均已完成。数据库属性编辑、真实 Kubernetes/SQL Server 环境等限制单列在最后。

- **通过（真实）**：浏览器操作后检查实际数据库、服务器命令、画布或回放内容；不是只检查按钮存在。
- **通过（受控）**：模拟断网、会话失效、主机密钥异常、协议帧等，验证浏览器状态和交互；不冒充真实外部系统联调。
- **部分通过 / 未验证**：明确缺口，不能计入通过数。一个自动化测试可能覆盖多个菜单动作，测试数不等于功能点数。
- 首轮失败中，由旧选择器、隔离测试实例路径、测试身份 Audience 等引起的环境问题已修正；下表记录最终复测结果。实际产品缺陷单列，不以测试适配掩盖。

### 本次实际发现的问题与修复

线上先点击/编辑第 1 行，再执行“全选 → 取消全选”，仍有 **1 行高亮**。原因是网格只清空了多选集合，没有清除父页面保存的单行选中状态。已修复为同步发出 `select(null)`。

- G04 新增先点击选中行的步骤，确认取消全选后为 **0 行高亮**，工具栏删除按钮禁用。
- 同样步骤已在远端实际数据库中复测通过。
- G06 新增实际数据库拒绝编辑的恢复验证：提交超长 VARCHAR 返回 400 后保留原值、重新加载，随后有效编辑仍能保存；不是模拟失败响应。

## 仍存在的缺口 / 本轮没有验证的范围

1. **“编辑数据库…”目前是只读属性查看。** 字符集/排序规则的实际修改未实现，不能标成编辑通过。
2. 无本轮可用 Kubernetes 集群凭据：真实集群浏览器用例跳过；后端协议模拟不能替代 Namespace/Pod/Container 的真实集群验收。

4. RDP 新会话实测对象是 xrdp；线上真实既有录像单独验收，不等于重新通过所有 Windows/NLA/域账户组合。
5. 本轮四格式导入导出和流式解析通过，但没有执行 2GB 文件与高并发/长时间浸泡压测。
6. 打印只验证浏览器调用和样式，没有验证打印机或每种 PDF 输出；PG 物化视图/所有触发器启停组合、每种设计器字段组合和所有浏览器/移动端没有逐一穷举。
