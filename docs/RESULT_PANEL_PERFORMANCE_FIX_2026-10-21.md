# 查询结果页签性能与树缩进修复（2026-10-21）

本次针对消息、摘要、结果、Profile、状态之间的切换，以及连接树逐层缩进。运行时代码只修改 `src/App.vue` 和 `src/styles.css`；没有提交或推送 Git。

## 原因与修复

Profile 原先在模板渲染时直接 `JSON.stringify(active.response.results, null, 2)`，会遍历并显示所有数据行。7179 行 × 24 列的本地模拟结果生成了 10,997,115 字符，切入 Profile 两次分别耗时 968.7 和 944.9 毫秒。先前性能回归只覆盖主工作区 Tab，遗漏了结果内部页签。

Profile 现在用惰性 computed 格式化执行元数据，保留结果序号、类型、列信息、行数、影响行数、最后插入 ID、截断标记、数据来源、总耗时、事务模式和警告，不读取数据行。状态页的格式化也移入 computed，避免无关更新重复格式化。其他页签现有的小规模统计保持原样；表格继续使用虚拟行，选中状态和滚动位置继续按结果保存。

检查了表格、对象列表、SQL 编辑器及通用页签组件的数据监听和序列化路径；没有发现与 Profile 同样在页签渲染中展开整份查询结果的路径。单元格复制、导出、JSON 编辑和打印仍在用户明确操作时处理所需数据。

树的层级缩进统一为 12 像素（原约 20 像素），覆盖数据库、Schema、分类、对象及共享树样式。展开箭头的点击区域保持 26 像素。
