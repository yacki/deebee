## 复现与测量

使用与线上发布版本相同的生产构建，在本机同一浏览器、同一测试中比较。模拟接口完整返回 7000 行、24 列字符串及主键；计时从点击运行/Tab 前开始，到结果可见并经过两次 requestAnimationFrame 结束。此结果衡量浏览器处理与渲染，不代表用户实际数据库查询时间。

| 项目 | 修复前 | 最终修复版本 |
|---|---:|---:|
| 查询结果显示 | 4558 ms | 278 ms |
| 三次切回结果 Tab | 4631 / 4460 / 4093 ms | 59 / 61 / 55 ms |
| 同时挂载的数据行 | 7000 | 25 |
| tbody 单元格节点，含行号/占位格 | 175000 | 626 |
| 接口返回及内存保留的数据行 | 7000 | 7000 |

修复前已复现多秒主线程阻塞。结果表格此前为全部行生成单元格；工作区的深度监听也会遍历各标签完整查询结果。这两个开销会随结果规模增长，不能只靠小结果功能测试发现。此处定位的是当前版本的瓶颈，未将两处已有实现都归因于本次 UI 迁移新引入。

## 实现

- `EditableGrid.vue` 对大结果使用可见区域和上下预留行，保留完整数据及真实行索引。滚动、跳转、编辑、选择均使用原结果行号及主键。
- `App.vue` 的工作区监听只包含实际保存的草稿字段。查询结果、加载状态、远程会话状态不再进入自动保存的深度遍历；SQL 草稿及结构设计修改仍能保存。
- 编辑行滚出窗口前保存修改；结果数组已更换时取消旧编辑，防止将旧行应用到新结果。编辑输入框在 24/30 像素行高下保持行高，避免影响虚拟滚动的位置计算。
- 更改行高保留当前浏览位置，ResizeObserver 跟踪可见区域。显式打印操作先挂载完整结果，结束后恢复可见区域渲染。
